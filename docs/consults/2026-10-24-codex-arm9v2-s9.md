## Cut 1: store collision after formatting

The short-read port now selects a raw hit word and builds the potential
store-merged word from W's already registered data and four byte enables.
Both words are formatted in parallel. The accepted-store/same-word/way
qualifier selects the finished result. The FSM's full-line write-enable
selection no longer precedes the byte merge and load formatting. No new
pipeline edge or cache-ACK admission path is introduced.

The victim-line merge, physical RAM writes, fill handling and ZAP's long
port are unchanged. Only a live IDLE/HUM lookup can forward this store;
fill and saved uncached-store owners are separate states. Simulation
assertions check that the live store's full-line data and enables equal
the registered W payload used by the factored path. The source-RTL cache
checks pass 21/21 with those assertions enabled.

All three configurations pass 267/267 and 69 QEMU comparisons. Every cycle
and instruction pair equals session 8. All 85 raw timing intervals at
0:0 / 0:3 / 2:9, with prediction on and off, are identical; the hit windows
remain 3/4/5. All four top-level lint combinations and cpu-gen-check pass.
[Validation](arm9v2/s9-cut1-validation.json).

The seed-2 trial improves hot slack by 0.311 ns and saves 65 ALMs.
Cold slack is -2.439 ns (essentially unchanged). This pays modestly,
but does not meet the structural target; continue with return repair.
[Fit and path evidence](arm9v2/s9-cut1-seed2/manifest.json).

## Cut 2: bounded normal-return repair

Normal retirement carries a six-bit return owner instead of a 64-bit
one-hot selector. Four S and four A repair comparisons are captured on the
same edge as the return data. S compares the next admitted D2 owner or its
held owner; A compares the accepted S owner or its held owner. The lock is
still checked *after* the accepting edge, indexed by the registered return
owner, so a miss ACK that installs a lock cannot release a consumer.
Only the resulting ready bit qualifies the eight local matches.

The background C selector/data already arrive registered, require no lock
qualification, and keep their existing local operand selection. Pending
and live-producer age checks retain priority over either retired return.
Repair still wins BX/SWP/block raw operand captures; exceptions and flushes
clear the new match records. No ACK enters admission or forwarding.

All three configurations pass 267/267 and 69 QEMU comparisons, with every
cycle/instruction pair and all 85 windows equal to session 8. Source and
generated execute benches pass 68,939 checks; decode and front-end/cache
component checks pass. All four lints and cpu-gen-check pass.
[Validation](arm9v2/s9-cut2-validation.json).

Seed 2 gains another 0.132 ns hot / 0.109 ns cold, at a cost of 93 ALMs.
This pays on timing; area remains above the target.
[Fit and path evidence](arm9v2/s9-cut2-seed2/manifest.json).

## Cut 3: independent D1 destination selection

Each registered D1 slot computes the few exceptional lane-0 destinations
in parallel: a block-transfer register, multiply's Rn destination, link
register, or banked SPSR. Finished physical tags are selected with the
registered queue-head bits. The complete priority classifier still supplies
the instruction kind, but no longer controls the destination-tag mux.
The fast direct-branch path and subsequent block-list steps are unchanged.

A Yosys SAT miter proves the new destination function equals the original
kind-based selection for all combinations of instruction, Thumb class,
mode, undefined bit, list count/PC bit and first register. This includes
invalid and empty-list cases, and all bank mappings.
[Reproducible miter and proof](arm9v2/s9-destination-proof/manifest.json).

All three configurations pass 267/267 and 69 QEMU comparisons; every
cycle/instruction pair and all 85 raw windows remain identical. Decode
passes 6,586,943 checks in both source and generated forms; the cache
integration passes all three latency variants. All four lints and
cpu-gen-check pass. [Validation](arm9v2/s9-cut3-validation.json).

The D1 candidate does **not** pay at seed 2: hot slack regresses by
0.514 ns, cold by 0.536 ns, and area grows 307 ALMs. The passing functional
candidate and its proof were committed as `c6b7113`; `95dfb2e` restored
the exact cut-2 RTL and netlist hashes before the RF experiment. No second D1 variant or seed sweep is attempted.
[Rejected fit and paths](arm9v2/s9-cut3-seed2/manifest.json).

## Cut 4: retain the RF storage boundary

The RF's HDL storage and port logic are unchanged from S6. The fitter's
optimization report identifies physical retiming as the source of the
extra storage, with derived `mem[...]_OTERM...` registers. It records 3,130
RF retiming events in S6 and 6,669 in S8, versus only 97 and 42 router
replication events. Events are optimizer operations, not unique final
registers. The RF's fitted register counts are 1,874 / 3,604 / 4,454 / 4,149
for S6 / S8 / cut 1 / cut 2. Its allocation therefore also moves sharply
when logic outside the unchanged RF is restructured.
[Optimization evidence](arm9v2/s9-rf-optimization.json).

The experiment sets `syn_allow_retiming=0` on the existing `mem` array,
through a V2-only writeback parameter. ZAP keeps the default value 1,
which has no effect according to the
[Quartus attribute documentation](https://docs.altera.com/r/docs/683283/18.1/design-compilation-user-guide-quartus-prime-standard-edition/disabling-synthesis-netlist-optimizations-with-dont_retime-attribute?contentId=BMeT8DJa8ap5HGdSqHe8_g).
The write ports, their C-over-B-over-A priority, reset and four read ports
are unchanged. No RAM rewrite or new read latency is involved.

This isolates the RF retiming boundary, not one individual S7/S8 consumer:
the available fits establish the optimizer mechanism, but do not establish
which added consumer first caused its cost function to choose replication.
No consumer-by-consumer ablation or additional timing seed is run.

An initial RF compile was stopped during analysis because Quartus 17
rejected the one-bit attribute value `1'b0`. The parameter and override
now use integer `0`/`1`, which Quartus accepts. That aborted analysis has
no fitted result in the trend table. The firmware run was restarted from
the corrected source rather than reporting the aborted candidate.


The final RF fit is **16,561 ALMs**, 1,816 below cut 2 and 1,788 below S8.
It is only **12 ALMs (+0.073%)** above the historical same-wrapper ZAP
reference of 16,549, comfortably inside the 5% area limit. No new ZAP fit
is claimed. The RF itself falls from cut 2's 3,189.1 ALMs / 4,149 registers
to **1,399.5 ALMs / 1,280 registers**. No RF register-retiming events remain.
Almost all of this cut's area saving is therefore directly accounted for
inside the RF hierarchy. Total registers are 17,229, with 71 M10Ks and 4 DSPs.

Timing does **not** pass: hot slack is **-2.871 ns**, cold **-2.865 ns**,
0.476 / 0.535 ns worse than cut 2. Minimum hold slack is +0.130 ns.
Retain the RF boundary for its substantial area correction, but stop here:
the final source remains below the -2 ns guardrail and misses the requested
approximately -1.6 ns target by 1.271 ns. It is 2.287 ns behind the historical
ZAP -0.584 ns reference. This session has not achieved 104 MHz timing.
[Final fit](arm9v2/s9-cut4-seed2/manifest.json).

## Remaining chains and exact RTL stopping point

The final worst 30 paths at each slow corner are retained in the fit
artifacts and [a compact path table](arm9v2/s9-final-paths.json).

| Remaining family | Hot data delay | Logic levels | Routing share |
|---|---:|---:|---:|
| D-cache lock -> W lock reduction -> `wb_complete` -> next producer tag -> A late match | 11.803 ns | 9 (adjacent lane: 10) | 65% |
| Registered memory state -> request/translation control -> D-TLB `o_hit_ok` | 11.588 ns | 8 | 65% |
| W load owner -> cache valid metadata | 11.595 ns | 7 | 68% |
| W load owner -> short-RAM forwarding write record | 11.618 ns | 6 | 73% |
| A late-match control -> cache metadata / short forwarding | 11.557 / 11.580 ns | 8 / 7 | 65 / 70% |

The first path is specifically `lock_ff[21]` through `WideOr0`,
`wb_complete~2/~6` (fanout **163**), `always2~5`, `forward_tag[0]~6`, and
`a~36/~39` into `a[52]`, the store-data operand's next M-producer match.
The cold counterpart is 11.808 ns / 9 levels; its adjacent lane is
11.771 ns / 10 levels. This is W completion selecting the *next live*
producer record, not the retired normal-return selector removed in cut 2.
It occupies 13/30 hot and 22/30 cold paths into A, plus one cold path into
D2/S's `o_forward_match` (10 levels / 11.442 ns).

Cut 1 factored the data merge using existing registered W payloads; it did
not add a registered accepted-request controller. Live request/translation
control therefore remains. Cut 2 bounded the normal retired-return repair;
it did not remove W's separate 64-bit lock reduction from completion and
next-producer selection. D1 retains the original classifier-dependent
destination selection because its measured replacement was rejected.

No further RTL feature or timing cut is made after these four experiments.
The next structural work is the W-completion/next-producer match boundary,
with the same-cycle newly installed miss lock preserved, and a registered
request owner for translation/cache control. Several remaining endpoints
are the metadata/short-forwarding structures owned by memside4; evaluate
that validated merge before duplicating its work. The tag-RAM file remains
untouched here. No additional seed, whole-device fit, or board performance
claim is made. The user's separate measurement build is not this CPU trial.

Firmware verification of this final source is still running at the RF-cut
milestone; its completed comparison will be recorded below before the
session ends.
