# ARM9V2 session 2: front-end timing and D1/D2

Both session milestones are complete as components. The same-cycle front end
now meets 104 MHz in all three fits, median worst-slow slack **+0.712 ns**,
versus **-0.856 ns** in session 1. D1/D2 is implemented and tested standalone
and with the front end/cache. Its combined frontend/decode/RF fit has median
worst-slow slack **-0.890 ns**, **4,159 median ALMs**; it does **not** close
104 MHz yet. Predicted throughput stays one record per clock; unpredicted
hot branches lose six slots, three above the design target.

ZAP remains default and all existing CPU cycles are unchanged. `CORE="ARM9"`
still selects the paused implementation. V2 S/A/M/W and retirement do not
exist yet; neither a complete-CPU fit nor gameplay performance is implied.

## Front-end timing rounds

Section 1 of the requested main-worktree Antigravity consultation was read,
along with the session-1 worst paths for seeds 2–4. The old front end's 30
worst paths at each worst slow corner fed the next lookup's `read_valid`.
Seed 2 ran through the valid-array selection; seed 3 also exposed the
same-index collision comparison; seed 4 included the return-target choice.
Their worst data delays were 7.909 / 8.132 / 8.229 ns, six or seven logic
levels, with approximately -2.1 ns RAM-to-flop clock skew. Selecting the next
PC was followed by another address-dependent control calculation.

Round 1 moves both checks to registered lookup metadata. `read_valid` now
snapshots all 256 validity bits, with same-edge feedback applied. The bit
selection uses registered `read_pc`, in parallel with the RAM tag comparison.
Unlike reading live validity after the lookup, the snapshot cannot turn a
held miss into a hit when a later update changes that index. A new directed
test checks this case. The extra bitmap flops largely occupy spare ALM
register capacity.

The shared RAM's opt-in `REGISTER_COLLISION` captures read/write addresses,
write enable and data. Its collision comparison runs after the edge, beside
the RAM read response, and retains write-first data through held cycles.
Existing callers retain the default implementation. No D-cache source was
changed. This removes the late launch address -> collision compare -> flag
register path while keeping exactly the original lookup/collision latency.

Round 1's new worst path was RAM -> tag decision -> selected launch ->
sequential-PC increment. Round 2 computes the predicted and sequential
continuations independently, then selects the finished value. Explicit
`keep` wires prevent the two sums being folded into a shared adder after the
late decision. There is no additional pipeline stage.

## Consultation checklist and scope

- One common forwarding network with three registered producers remains the
  S/A design contract. D1/D2 has raw RF reads and same-edge RF
  write-through only. A/M forwarding and background-load producer capture
  belong to the later execution/memory milestones.
- PC-relative targets belong in decode, comparisons use registered targets,
  and redirect events/payloads must be registers. No combinational execute
  event may drive fetch or decode admission.
- Fetch status only qualifies queue insertion/status. The front end has no
  cache-response bypass or Thumb decoder. D1 owns the one expansion.
- Block population count/first selection must precede RF read. Later list
  scans must terminate at registered register indices, not feed RF muxes in
  the same cycle.
- D-cache byte merge/format placement is outside this session and those files
  remain untouched. The registered-address M/W design, D-stage hazards and
  registered capacity must prevent live ACK/err2 propagating through S/A.

The consultation's claim of zero extra cost while retaining a two-clock
load-use was for the older five-stage proposal, and was not demonstrated by
its integrated timing. It does not override V2's explicit three-clock
registered-address load-use design. Likewise its two-clock predicted branch
row is superseded by V2's measured one-word-per-clock fetch cadence; complete
instruction timing still needs the backend. The structural recommendations
are adopted; unmeasured cycle guarantees are not treated as evidence.

## D1/D2 implementation and verification

The decode component is `rtl/cpu/arm9v2/arm9v2_decode.sv`; the integration
harness is `sim/cpu/arm9v2/front_decode.sv`. It includes the real ZAP register
file and the registers at the S entrance. No execution, memory ordering or
retirement is simulated by this harness. `CORE="ARM9"` continues to execute
the paused core, so its QEMU comparisons are regression protection, not a
claim of V2 architectural completeness.

The queue supplies one raw word, PC/state, mode, fault, prediction and RAS
checkpoint. One Thumb expander selects the correct halfword at D1 acceptance.
Two D1 slots absorb downstream backpressure; frontend capacity comes from
registered occupancy. Parallel balanced list count/first-selection trees
capture ARM lists and Thumb implicit LR/PC. D1 classification/banking and
PC-relative addition end at D2 registers before any RF selection. D2 has
four physical source indices, usage bits, two destination indices, condition,
kind, target and block sequencing state. All architectural banks, including
SPSRs, are represented.

D2 reads the raw RF. The only bypass here is the RF's same-edge C>B>A
write-through. Registered source locks stop D2 before S; no producer search
or readiness enters the RF value muxes. S still must substitute architectural
PC/CPSR values (including register-shift PC and Thumb alignment) from the
attached metadata; raw RF contents are not those values. Used-source qualification excludes
irrelevant encoding fields and LDM destinations. Final LDM PC+S reads its
SPSR; user-bank block transfers retain their original base bank. The initial
base value must be retained by the future backend, which also owns writeback,
base restoration, conditional execution and precise aborts.

Block transfers use ascending register order and signed eight-bit offsets:
IA 0, IB 4, DA -4n+4, DB -4n, then +4 per transfer. Writeback delta is +/-4n.
The next scan ends at the index register, followed by RF read on the next
cycle. A source hold stops that record; downstream hold keeps the S payload
stable. There is no fixed drain between transfers. Empty lists become
undefined. A fetch fault produces one operand-free record regardless of
invalid instruction bits, preventing a faulted LDM encoding from expanding
or waiting for a locked operand.

Unconditional direct B/BL uses D2's target. The registered redirect carries
its checkpoint, RAS action and link. Taken/fallthrough equality includes the
Thumb bit and terminates in two S-entry bits for later validation. An adjacent
Thumb BL suffix uses the dedicated prefix-sum register (or the preceding D2
prefix's registered sum); an orphan suffix remains an LR-dependent late
operation. Conditional B, BX, ALU/loaded PC, SWI and status changes are not
resolved by this milestone. Older flush has priority over a local redirect
and invalidates younger slots/prefix pairing; a local redirect preserves its
own S record.

`make -C sim/cpu arm9v2-decode` passes **6,037,233 checks / 722,064 bench
clocks** in each of source and generated RTL. It exhausts all 65,535 nonempty
register lists, rotates addressing modes and checks full/sparse lists across
all banks and user-bank forms. Additional cases cover Thumb lanes,
PUSH/POP/BL (including negative/max offsets and wrong predicted state), RF same-edge write priority, used/unused locked sources, holds,
faulted list bits, predicted/unpredicted direct targets and flush priority.
The real short-read I-cache/TLB integration passes at bus waits 0/3/9:
**1,146 / 1,573 / 2,485 checks**, **442 / 649 / 1,105 clocks**. It checks a
trained/untrained branch loop, full-queue recovery, Thumb, LDM/STM source
holds, translation faults and a redirect during an outstanding fill.

Source component lint, top-level `make lint`, `make cpu-gen-check`, and the
existing frontend tests pass. sv2v emits the legacy Thumb X literals and
flattened unused struct fields differently; generated unit lint suppresses
only those width/unused-signal warnings. Source lint remains strict. The CPU
netlist is regenerated and byte-identical to the frontend milestone, because
the new decode has not yet been selected by the CPU top.

The full existing suite was rerun after decode: ZAP **261/261**, paused ARM9
on/off **258/258 each**, **68 QEMU agreements each**, zero differences. Every
one of the 777 cycle/instruction pairs equals session 1, including all random
and compiled rows. The cycle table above therefore applies to both session-2

## D1/D2 measured cycle limits

An accepted input produces its first S-entry record two edges later. An
n-register block reaches its last S-entry record at acceptance+(n+1), or
n+2 inclusive edges. Transfers are consecutive. This is decode throughput,
not a claim that a retired LDM/STM already costs n+2: the execution, cache
and abort paths do not exist yet.

The trained three-target branch loop emits **one record per clock** through
F1/F2 and decode at all bus waits after warmup. The same hot loop without
training emits a record every **seven clocks**, or **six lost slots**, against
the design target of three lost slots. This is a measured shortfall, not a
retargeted requirement. A registered D2 redirect is applied next edge; launch
waits another edge, then F1/F2 and the raw queue/D1/D2 handoffs refill S.
Eliminating redundant redirect/empty-queue handoffs needs a separate timing-
checked change. This milestone preserves the common predicted cadence and
keeps cache permission/validity entirely outside decode data selection.

No V2 workload cycle, CPI, three-clock load-use or game rate can be reported
yet. Future S/A must add the single three-producer network, late pickup,
conditions/flags and multiplier. M/W must add a registered address, registered
load returns, precise exceptions, CP15 ordering, base restoration and the
non-blocking cache interface. Do not use the component pass to enable V2 by
default or to start whole-device integration.
