# V2 lane D: the D-TLB's o_wt into decode (2026-10-25)

Item 3 of the lane C/D/E request: the device path at −2.29 from the
D-TLB's write-through bit into D2. The plan's family D is
[2026-10-25-v2-104mhz-plan.md](2026-10-25-v2-104mhz-plan.md) §1 D.

**Commit:** RTL `5a381d4` (`zap_tlb_check.sv`, `zap_tlb.sv`,
`zap_cache.sv`, `zap_dcache.sv`, `zap_top.sv`, the regenerated netlist).

There is no new test: the boundary's function is unchanged (see below).
Nothing was pushed, and nothing went to the board.

## What the path was

The path on lane B's device (`dev_family_decode_redirect`):
- `o_wt` → `o_hit_ok~0` → A's `a_wait` → `o_a_can_finish` → D2's
  `step` → `pop` → `new_d2` → `redirect_ff`/`d2`.

**`o_wt` is not a core control signal here.** Quartus's register
retiming had moved `zap_tlb_check`'s `o_hit_ok` register back across
its AND. The short hit, `tr_cache_hit && tlb_hit_ok`, was therefore
rebuilt at the CPU's edge from `o_wt`, `o_fsr`, `o_cacheable` and
`o_walk`. The CPU trial does not retime, so only the device had this.

## The registration, zero cycles

**`HIT_FF`** gives the D-cache's short hit its own copy,
`o_hit_ok_short`.
- It is loaded with the same term on the same enable.
- It is marked `dont_retime` and `preserve`.
- The cache's own users (the HUM ACK, live writes) keep the retimable
  `o_hit_ok`.
- The copy is asserted equal to `o_hit_ok` on every clock, so the short
  hit's timing and meaning are unchanged; no test is needed for a new
  boundary.
- It is on for ARM9 in `zap_top`. ZAP's short hit is constant 0.

**Device** (lane B → round 1 → round 2; lane C has the setup):
- **`decode_redirect`:** −2.291 → −2.104 → **−1.556**. It is now led by
  A's record → `redirect_ff`, not the TLB.
- **The cost moved to the copy's D side:** `dtlb_hit` +0.107 → −1.474 →
  −0.713, and `decode_issue` +0.084 → +0.007 → −0.454 (`o_hit_ok_short`
  → `issued`).

## What is left: the registered-ready shape, reported, not taken

**The CPU trial's worst** after C+D+E is −2.309:
`o_hit_ok_short` → `a_load_hit` → A's finish → S's `space` → D2's
`step` → `pop` → `redirect_ff`'s enable.
- The hit is now a clean low-fanout flop. What remains is the ready
  chain itself: W's hit decides whether A finishes, which decides
  whether S has space, which decides whether D2 steps and the queue pops.
- **It is not a zero-cycle registration.** Taking it off the cycle needs
  a registered "S has space" for D2: a skid entry between D2 and S. D2's
  hazard and forwarding checks would then have to cover that entry,
  which is the transition class behind fixes 1-3.
- **The other option** is the plan's D1, a registered completion. It
  costs +1 per non-short completion, estimated at +1.0-1.3 %.

Both need the cost gate, so I stopped here.
