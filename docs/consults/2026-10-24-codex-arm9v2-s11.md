# ARM9V2 session 11 — short-port selection, S grants and retirement

Starting point: `c87d383`, final S10 RTL `c52222a`, on `codex/arm9v2`.
ZAP stays the default. This session preserves the complete cycle schedule,
including raw independent/late/early hit windows 3/4/5. Every integrated
trial uses Ubuntu, seed 2, 104 MHz, the S10 placement/router settings and
RF retiming bound. No local Quartus, LogicLock, seed search or sys changes.

## Acceptance and evidence

Each cut is checked against the frozen S10/S9 cycle/instruction pairs:
267 runs and 69 QEMU agreements for ZAP and V2 predictor on/off; 85 windows
at all three latencies in both V2 modes; four CPU/debug lint combinations;
regeneration and cpu-gen-check. Existing binaries and QEMU references are
reused. Per-cut JSON evidence identifies the exact generated netlist.
Independent endpoint-family queries are retained, rather than treating the
global top thirty near-duplicates as the complete timing picture. A dash
in a before column means that endpoint was not separately queried in the
preceding session, or the register did not yet exist; it is not zero slack.

## Cut 1 — short RAM descriptors and banked metadata capture

`zap_cache_tag_ram.sv` now gives the short cache one registered read/write
set descriptor, common tag/line write data and per-way tag/byte enables.
The read-first M10K edge is unchanged. One equality after that edge selects
the captured write bytes/tags on a collision. Byte RAMs use independent
8-bit `zap_ram_simple` instances with `SHORT_RAW=1`, exposing the original
registered read-first word without the lane-local bypass. The default
parameter preserves every existing caller. The three-edge RAM instances are
still used by the non-short generate branch.

Short valid, dirty and LRU reads select at most sixteen entries per bank
before the edge; registered upper address bits choose the bank afterwards.
The read set, live write and pending write descriptors are captured with
each output's original enable. Dirty uses `!hold || clean || line_clear`;
valid and LRU use `!hold || clear || line_clear`. These cannot be conflated:
a maintenance event may update one output while another stays held. Reset
clears the bank captures and bypass enables. Current writes override pending
writes in the read bypass, and current hits override fills for LRU. The
underlying arrays still apply pending writes before clean/invalidate/line
clear, with the original cache-disabled clearing behavior. Non-short
metadata expressions and array update priority are unchanged.

`sim/cpu/arm9v2/short_miter.py` obtains the immutable S10 golden module
from git and compares all module outputs and valid/dirty/LRU arrays and
read outputs on every edge. Its 896,616 edges cover 256/512-set two-way
short caches, a direct-mapped short cache and the non-short cache, accepted
HUM updates, every single-byte write mask, random multi-byte writes,
collisions, held accesses, cache disable, dirty walks, invalidation and
VA/index line operations. A deterministic maintenance tail guarantees
clean/invalidate/line coverage even when random traffic leaves a walk
unfinished. This is simulation equivalence, not an exhaustive formal proof
of all cache histories. Full CPU cache tests additionally exercise the
FSM's real fill/HUM and maintenance protocol.


The additional `short_meta_proof.py` extracts the new short metadata block
and S10's original capture expressions, then proves their equality
inductively with arbitrary array contents, live/pending updates, read
addresses and independent maintenance enables on every edge. Both 256-
and 512-set proofs pass. This proves the capture transformation for all
such histories; the full-module miter checks the unchanged array writes,
RAM bytes, FSM and external outputs together. Models and Yosys logs are
saved as `arm9v2/s11-short-meta-{256,512}.{v,log}`.

Cut 1 passes all three generated suites (267/267, 69 QEMU each), all 85
windows at all latencies in both modes, all four lints and cpu-gen-check.
The source assertion suite additionally passes 267/267 with every pair
unchanged. See `arm9v2/s11-cut1-validation.json` and `s11-short-miter.log`.

### RAM inference failure and correction

The first candidate used inline byte/tag arrays inside the cache module.
Its behavior passed the miter and suites, but Quartus 17 mapped them to
flip-flops: 284,506 registers, only 51,616 block-memory bits, and 123,410
combinational nodes against 83,820 available. Fitting stopped before
placement; there is no slack/ALM result to claim for that candidate. Its
source identity and failure summaries are in `s11-inline-failure/`. A
concurrent cut-2 build using the same arrays was stopped once this was
known, before it could waste a second failed placement run.

The correction uses the existing module-level RAM inference template,
with a short-only raw-output parameter. The common cache descriptor still
owns collision forwarding; its address registers are bounded against
retiming. The full miter and inductive metadata proof pass again. The
following reported fits use this corrected source; the failed inference
attempt is not a seed comparison or a timing result.

## Cut 2 — data-ready grants beside the full producer matches

D2/S still captures the full writer-qualified matches used for producer age,
pending protection and held-operand repair. A separate register now holds
the five one-hot data grants for each source: M lane 1/0, W lane 1/0, or
RF/held fallback. M's load-writer exclusion and the lane priority are
resolved before this edge, refreshed on every hold exactly like the owner
matches. S's forwarding module is just a masked data OR tree.

W's short-hit permission and `w_waited` become known on the same edge as
that operand record. Guessing them a clock early would be wrong on a miss
or a held lookup. Instead D2/S captures both finished grant alternatives
(W load unavailable/available); the registered short-hit predicate selects
one in S. No producer load-owner mask or priority calculation remains in
the S data selector, and no ACK qualifies admission. Full matches and the
existing pending/repair logic remain unchanged. Assertions check exact
old-selector equivalence, one-hot grants and availability of every selected
producer on every valid S edge, including held operands.

The standalone source/generated decode, execute and leaf benches pass,
as do their cache integrations at latencies 0/3/9. The full source suite
checks the grant assertions and preserves all 267 cycle/instruction pairs.
The fitted source was frozen in an isolated copy while cut 1 finished;
its RTL and generated-netlist hashes exactly match the promoted source.

## Cut 3 — parallel next-lock queries and RF owner class

The cache now queries `lock_nxt` at both registered candidate destinations
(held W and advancing M) in parallel. `keep` preserves these two queries;
completion/reload selects their finished one-bit results at the existing
summary register. Reset and the actual W movement schedule are unchanged.
The global non-empty summary still uses the same next bitmap. The updated
inductive proof extracts the real query and register expressions and allows
arbitrary next bitmaps, both owner tags and transition decisions. Every-edge
runtime comparisons additionally check the actual W owner, including
simultaneous lock installation and clear.

W captures the static RF exception class with its next record. Completion
still determines architectural write enable, retirement, CPSR, exception
entry, PC and trace. It no longer selects RF port data. A data abort is the
only late class override; abort restoration suppresses the exception class
so the original base write happens first. CP15 retains its original
priority below exceptions. The V2-only RF path compares selected ports and
both data words with the original writeback tree on every enabled write.
The per-register A/B data mux uses the owner class independently of the
common write enable; background C still wins over B and A. The integer
RF retiming bound remains zero for V2. ZAP and the legacy ARM9 use the
original selector and RF update branch.

All three configurations pass 267/267 and 69 QEMU comparisons, all 85 windows
remain exact, all four lints and cpu-gen-check pass. Source assertions pass
267/267 with identical pairs; the legacy BTB bench also passes. The fitted,
firmware-run and promoted RTL/netlist identities match. The bounded
firmware run is still in progress at this cut commit. See
`arm9v2/s11-cut3-validation.json` and `s11-lock-summary-proof.{v,log}`.
