# ARM9V2 session 8: retained scalar-load consumers and first firmware

Starting at `4616d9c`, on codex/arm9v2; ZAP remains default. No master merge.

## Recovery baseline

Bench-only counters classify scalar retirement recovery as (1) no first
short hit without a prior W wait, (2) held/retried without a short hit,
(3) eventual short hit after waiting. ZAP's existing replay bit is class 4.
The first class is not a bus-miss counter: the D-cache event counters remain
the source for cache fill/uncached transaction counts. Killed slots count
valid queue and backend uop slots, not deduplicated architectural instructions.
Refill clocks run from registered recovery to the next retirement, including
memory wait; they are not an exclusive frontend-stall CPI component.

All six requested tests at 0:3 and 2:9 pass on both cores, and every
cycle/instruction pair equals session 7. ZAP has zero replay events here.
[Raw measurements](arm9v2/s8-recovery-baseline.json).

At 2:9, cache has 24,662 recoveries, 315,049 killed slots and 279,692
clocks until retirement resumes. crand1 has 297 recoveries, 2,523 killed
slots and 8,142 refill clocks; 128 of the recoveries are eventual short hits.
These are observed occupancy costs, not an estimate of recoverable total cycles.

## Retained scalar completion

Scalar-load completion no longer requests a W flush. A registered operand
lock follows a released consumer into S/A. S waits for early operands;
A waits for late operands. A first permission-qualified short hit retains
the raw 3/4/5 independent/late/early windows. An unavailable word is never
selected. A registered normal completion or the cache's existing registered
background port C repairs the held operand, which survives subsequent holds.
The normal completion is qualified against the lock installed by its ACK:
a fill ACK is not usable data. No ACK is added to D2/S admission or forwarding.

D2 carries unresolved W ownership across the same edge that installs a cache
lock. Without it, dcache_rtl at 0:3 failed check 23, PC 0x7ac: a comparison
executed before the background return. WAW admission remains conservative,
except when a true source dependency already protects the overwrite or W
has a known hit. Abort/exception priority, partial LDM, SWP and PC loads keep
their prior protection. Independent work may retire with a background lock;
dhum_rtl at 2:9 records 1,441 such uops.

A held access can resume without the two lookup-reload clocks when both
reserved younger records are non-memory operations. Memory records still
use the original reload. An initial shortcut exposed a same-edge operand
repair priority bug: align at 0:3/2:9 branched to 0x98 instead of 0x950,
after BX at 0x94c. BX's raw Rm assignment overrode the repaired word. The
repair now wins all class-specific captures, including BX/SWP and the first
block base. Directed execute checks cover held background completion, an
early shifted consumer, and BX completion on its admission edge.

## Whole-core selection and bench integration

commented-macro default. NGage.sv passes CORE to arm925t; both selections
use the same shared caches, TLBs, CP15 and merger. NGAGE_DEBUG remains an
independent measurement option. The existing debug packet layout is

the common wrapper debug taps. Only the RF and data-owner PC require a
CORE-specific hierarchy. `make -C sim ... VEXTRA=-DNGAGE_CORE_ARM9=1 top`

worktrees to build without a Quartus-generated root file.

new retention tests. Decode passes 6,586,943 checks. The generated standalone
bench required an explicit 32-bit zero extension for its packed return-index
arithmetic; sv2v otherwise emits width warnings. This is an index-width
cleanup (all 64 index values are identical), not a schedule change.
The shared ZAP sources/cache FSM have not changed.

All four lint combinations pass: `make lint`, the debug ZAP lint, and both
stripped/debug lints with `-DNGAGE_CORE_ARM9=1`. `make cpu-gen-check` passes.
`tools/mister_dbg.py` successfully decodes the V2-rendered whole-shell debug

## First firmware divergence and producer-age regression

The initial V2 binary made 254 executive calls, then entered the kernel
halt loop at `0x5031e394` before user mode. It logged no ARM data abort,
prefetch abort or undefined instruction. The paired ZAP run proceeded to
kernel messages and user-mode entries, so the initial V2 result is a
firmware failure despite the passing CPU suite. The first 37,547 device
accesses agree with the earlier successful ZAP firmware reference.

A directed execute test exposes two age errors with successive loads to
one register: an older W short hit releases a consumer still waiting for
a younger M load; the older load's registered return can also clear that
consumer's pending bit. The test fails at cycles 39,198 and 39,199 as the
two cases are isolated. W may now release A only when no younger M match
shadows it, and retired returns repair S/A only when no live M/W producer
owns that operand. These checks use existing registered match bits.

The corrected source/generated execute benches pass 68,936 checks. All
three full suites and QEMU comparisons pass again; all 792 cycle/instruction
pairs and all raw windows at all three latencies are unchanged
([manifest](arm9v2/s8-priority-validation.json)). Four lint configurations
and cpu-gen-check pass. Firmware traces and the corrected firmware replay
are in progress; the unit result alone does not establish the cause of the
kernel halt or a successful V2 boot.

The assembly regression `loadchain.S` reproduces the complete-cache failure
on the pre-fix netlist at all latencies (check 1 at 50,935 / 77,206 / 144,137
clocks). It covers subtraction, flag-dependent control, an early shift and
late store data after two loads to the same destination, cold and warm.
It passes with the age fix. Only this new binary/reference was built and
run on QEMU. The final suite is **267/267 and 69 QEMU agreements** in all
three configurations; the original 264 pairs remain exactly unchanged.
The new test also agrees at both higher latencies on all three cores
([release manifest](arm9v2/s8-release-validation.json)). Whole-shell checks
pass again in the same 150,622,764 clocks.

The failing firmware trace confirms an actual stale-operand result at
`0x5032b12c`: `RSB r3,r1,r3` uses the preceding literal `0x80006680`
instead of the younger loaded zero. It produces `0xffc06680` rather than
`0x7fc00000`. Later, IRQ entry's `LDR ip,literal; LDR ip,[ip,#12]; CMP ip,#0`
takes the nonzero path even though the completed value is zero, and jumps
to zero. The reset handler calls the kernel's exception-fault routine with
reason `0x10000000`; there is no new ARM abort/undefined event. See the
[trace excerpts and artifact hash](arm9v2/s8-firmware-initial-failure.txt).

The first age fix (`e851278`) corrected all arguments through executive
call 185, including the bad subtraction, but then stopped retiring at
`0x50329e4c`, retired count 270,749,939. Its next dependent had a ready
ALU producer and retained an older load's pending bit. A new directed
check reproduces that deadlock. The final readiness selection walks W then
M, just like the data selection: a ready younger writer clears a stale
pending bit, while an unresolved younger load blocks an older hit.
A returned word may repair an operand only after live producers have left.

The GBA suite also exercises scalar loads whose destination equals their
base-writeback register. The load wins at retirement (RF port B over A), so
the M/W producer mask now suppresses the overwritten base-update lane for
that case. This covers word and halfword forms without changing the LDM
abort/restoration protocol. The assembly regression now includes an
immediate comparison after RSB and both cached load/writeback aliases.
Source/generated execute checks pass 68,939 checks. A fresh firmware run
uses exactly this regenerated netlist (SHA256
`8b97867f01618e98315243d3fabc99b752aafe700e21277447d13ddec60b0547`).


The completed readiness/alias candidate passes **267/267 and 69 QEMU
references** for ZAP and both V2 predictor settings. All original 792
cycle/instruction pairs and all 85 windows at each latency are unchanged
from the retained-load milestone. The extended `loadchain` regression is
51,789 / 78,127 / 145,433 clocks on V2 with prediction, versus
56,661 / 82,856 / 149,430 on ZAP (12,799 instructions each). The pre-age-fix
netlist fails its check 4 at 50,949 / 77,243 / 144,260 clocks. The final
[validation manifest](arm9v2/s8-checked-validation.json) records these results.
The current whole-shell bench again passes all checks in 150,622,764 clocks;
all four lint configurations and cpu-gen-check pass. The final firmware
replay remains the outstanding proof at this commit; timing is unmeasured.
