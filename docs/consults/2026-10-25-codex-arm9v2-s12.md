# ARM9V2 session 12 — cycle model

The session starts at `7ed5190` on `codex/arm9v2`. ZAP remains the default.
The goal is the phone's gameplay speed, about 47 M instructions/s. Boot and
synthetic cycles are proxies; neither establishes an in-play result. No
new timing cuts are authorized. There will be one integrated seed-2 fit at
the accepted endpoint, on Ubuntu only.

## Merge and baseline

The merge parent is `9037af9`, the master tip when the merge began. It
contains requested `f37e549` plus two documentation commits. Later movement
of master is not silently incorporated into this measurement. The merge
retains RAM valid/dirty/LRU metadata, deferred dirty write-back, the real
accepted-HUM replacement update, and S11's short data/tag collision compare
after the RAM edge. Short metadata captures retain separate lookup, live
probe, clean, invalidate and line-operation enables. Normal-port equations
remain master's. The hardware QSF enables 16 KB D-cache; the CPU suite's
historical default remains 8 KB, so both sizes are measured explicitly.

`sim/cpu/arm9v2/metadata_miter.py` compares every module output and registered
metadata against the incoming master implementation for 896,616 edges:
short 256/512-set two-way, short one-way, and normal-port configurations.
It covers byte masks, held lookups, fill/store collisions, accepted HUM,
cleaning, invalidation and line operations. Fill/HUM bursts respect the
FSM's one-entry deferred-LRU contract. It is a randomized cycle miter,
not an unrestricted formal proof. The metadata, early-restart/error and
fetch-handshake unit benches also pass.

All six CPU configurations (ZAP, V2 prediction on/off, each D8/D16) pass
276/276 with 69 QEMU comparisons. The 85 windows are unchanged at all three
latencies and both prediction settings, including raw hit windows 3/4/5.
The V2 source/assertion suite adds 276 passing runs. A fresh model built
from the exact merge parent proves every ZAP cycle/instruction pair equal
at each cache size. Existing binaries and QEMU references were reused.
All four CPU/debug lint combinations pass at both cache sizes; gen-check
passes. Observation-only V2 fetch wait/full taps now drive master's new
fetch-counter assertion, with no change to queue control.

## Early execution

The merged V2 already consumes the early words. It pushes on the cache's
ACK, not its hit-only signal; the queued pending bit obeys execution
quarantine. Master's `icexec_rtl`, `icwf_rtl` and `ifetch_rtl` pass on both
V2 modes, including retirement from critical offset +12 before the fill
ends. Guaranteed classes release valid words; error-capable fills keep the
quarantine and late-error checks. No redundant hit bypass is added.

A same-source V2 counterfactual forces the SoC guarantee sideband low.
First executive call moves from 338788765 to 338789258 (+493 clocks), and
EFile from 377614699 to 377620050 (+5351, 0.00142%). This is a measured tiny
boot benefit, not evidence of a large fetch gain. The 16 KB geometry and
other merged changes must not be attributed to early execution.
EStart moves from 432404714 to 432421584 (+16870, 0.00390%). Full paired
logs and thread identities are in [firmware evidence](arm9v2/s12-merge-firmware.json).
This item needs no extra fetch RTL: the merge supplies the guarantee
contract to the existing ACK/quarantine handshake.

## Serial operations

The implementation and window table are in docs/ARM9V2.md's session-12
section. Flags-only CPSR writes keep A's ordered NZCV. Same-mode control
writes release D2 from a registered A result, with a registered I/F copy;
actual mode/SPSR changes still recover at W. Ordinary CP15 reads keep
independent younger work and mark their destination unavailable until
completion. MRC-to-PC retains a local flag interlock. All MCR/maintenance
operations retain their conservative ordering and costs.

The directed test caught a real integration issue: ZAP writeback borrows
RF port A whenever CP15 enables its register interface, including MRC.
Without the old global fence this corrupted a younger Rn read. V2 now
keeps D2's port-A address for MRC; only fenced MCR borrows it. ZAP is
unchanged. No shared-cache ACK is added to admission or forwarding.

All six configurations pass 282 runs with the two new tests and 71 QEMU
references; source assertions pass 282 more. The original 85 windows keep
raw 3/4/5; five serial windows improve. Four new block-tail windows record
the pre-change dependent cost, 7/9 for one/three registers. ZAP's existing
276 pairs remain exactly master's. The interrupt benches can execute a
different number of polling instructions after mask-write timing changes;
non-interrupt test instruction counts are unchanged. Their signatures,
precise exceptions and QEMU comparisons remain the acceptance evidence.

## Small LDM tails and PC returns

Only the final non-PC block word receives scalar late-consumer eligibility.
The earlier words retain their protection, locks and abort base restoration.
New marker windows: LDM1+ADD 7 to 4; LDM3+ADD 9 to 6; shifted consumers 7 to
5 and 9 to 7. The existing independent LDM1/LDM3 windows remain 2/4. This is
not a claim that every multi-register load's dependent tail is now optimal.

A first-pass, permission-qualified PC hit retires using the registered
short word without the redundant LOAD_RETURN save. W still captures the
one-shot redirect and RAS repair; abort priority, L4/Thumb target selection
and SPSR return rules are unchanged. Held/retried/missed/uncached PC loads
and SWP retain the conservative path. Source assertions prove that an
accepted fast PC hit's short word equals the normal formatted return.
Predicted LDR-PC's warm window improves 5 to 2; final LDM-PC 14 to 13, with
the preceding 19-clock visit unchanged. Vector-table LDR-PC similarly cuts
three clocks from the measured predicted-mode exception-entry windows.

All six configurations pass 282/282 and 71 QEMU comparisons. The source
assertion suite passes 282/282. The original 85 windows plus four dependent
LDM windows are measured at all latencies, D8/D16 and both predictor modes;
raw scalar 3/4/5 is unchanged. ZAP's master-reference pairs remain identical.
Firmware is running from a separate frozen endpoint snapshot. The
post-setup 2:9 V2/ZAP ratios are still only 0.974 crand1, 0.969 ctrand1 and
0.972 mmu_page (D16): these changes do not establish the intended 35-50%
gain. The firmware milestones and eventual gameplay measurement are needed.
