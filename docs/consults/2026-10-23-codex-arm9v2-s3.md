# ARM9V2 session 3: decode timing, cold redirects and S/A

The first milestone is complete: frontend/decode median worst-slow slack
improves from -0.890 to **-0.210 ns**, and hot untrained direct branches lose
**three slots instead of six**. Predicted branches still lose zero slots.
Median area rises from 4,159 to 4,666 ALMs. ZAP remains default; V2 still has
no architectural retirement. CPU comparisons protect existing implementations
and are not claims about V2 game speed. S/A now passes component tests at **-1.729 ns median worst-slow** and 6,387
median ALMs. It stays above the -2 ns stop threshold but has not met the
-1 ns integration gate; memory completion and precise retirement remain open.

## Goal and scope

The goal is matching the phone's games on the board: Asphalt's 21 fps cap,
smooth Tony Hawk and Sonic's teens-to-twenties. The 47–48 M instructions/s
estimate comes from Asphalt's approximately 2.3 M instructions/frame. It is
a yardstick for that outcome. Firmware-invisible implementation choices may
change; the observable ISA, CP15 identity, exceptions, MMU and timers remain.
A CPU/component fit does not establish whole-device timing or gameplay speed.

## Structural pass before S/A

The starting point is session 2 commit `7f42e7a`. Its frontend/decode/RF/S-entry
component had median worst-slow setup slack -0.890 ns and 4,159 median ALMs.
Section 1 of the Antigravity consultation and all three session-2 worst-path
sets were reviewed before editing. The named families were:

| Seed / worst corner | Shared family | Levels | Data delay ns | Skew ns |
|---|---|---:|---:|---:|
| 2 / -40C | queue head, fanout 256 → queue mux → halfword select → Thumb expansion → D1 | 7 | 9.608 | -0.534 |
| 3 / -40C | queue head, fanout 255 → queue mux → list count → D1 | 6 | 10.087 | -0.510 |
| 4 / -40C | queue head → queue mux → list count → D1 | 6 | 10.233 | -0.102 |

The worst 30 paths grouped as Thumb/list/branch-target were 11/1/18,
2/24/4 and 0/30/0. D1 head → D2 target also reached 9.890 ns at seven
levels in seed 2 and 10.137 ns in seed 3. These are data delays; setup
slack also includes clock skew and endpoint requirements.

The pass replaces the fetch queue's binary head with a registered rotating
one-hot selector. Selection remains entirely over stored raw words and
metadata; cache hit/permission status never bypasses the queue into decode.
List population count uses three six-input truth tables, a carry-save
reduction and one five-bit sum. The first-bit removal uses parallel prefix
masks instead of a subtract-and-mask chain. Complete ARM, Thumb, prefix and
suffix branch sums are computed in parallel before selecting the target.

Cold direct branches had three avoidable handoffs. The registered redirect
now launches the cache lookup on its applying edge instead of first copying
its target into the sequential-PC register. An unpredicted direct branch
emits its registered redirect when entering D2, preserving that D2 owner
through the subsequent younger-record kill. With D1 empty, simple
unconditional ARM B/BL or Thumb B can enter D2 directly from the registered
fetch queue using dedicated trivial controls and target sums. Other
instructions retain the ordinary D1 path and single Thumb expander. This
shortcut is a measured latency choice, not a cache-response bypass.

Correct predictions do not redirect. Predicted wrong-target branches still
validate against the registered target at D2/S. Such an older late redirect
wins over a younger early event accepted at the same edge. Older backend
flush wins over both. A blocked S slot retains the early-redirect owner in
D2 until it can issue, without duplicating the pulse. During an outstanding
cache lookup, the existing killed/drain/restart path still preserves the
request until acknowledgement; immediate target launch applies only when
the cache pipeline can advance. Faulted words never take the shortcut.

## Timing correction within the pass

The first seed-2 trial of the redirect shortcut was -1.105 ns worst slow,
4,472 ALMs. All its worst 30 paths ended at the redirect payload register.
The queue-to-Thumb-target path had six reported logic levels but two serial
carry chains: PC + displacement, then +4. Its worst data delay was 10.442 ns
with -0.108 ns skew. The queue selector fanout had fallen from 255–256 to
115, but putting the PC bias after a full sum consumed that saving.

The corrected shortcut uses carry-save XOR/majority logic for PC,
displacement and bias, then one carry-propagating sum. A separate nine-level
D1 path was full instruction classification → branch-kind selection → target
selection → redirect payload (10.285 ns). Target selection now uses shallow
raw branch/prefix/suffix class bits rather than the complete ISA classifier.
The functional event priority, stage boundaries and cold/predicted cadence
are unchanged. Directed tests add 4,096 ARM and 4,096 Thumb targets, signed
negative displacements, both Thumb lanes and PC wraparound. Final decode
coverage is 6,061,854 checks / 746,659 clocks for source and generated RTL.
The earlier 6,037,278-check run is retained as pre-correction evidence.

## S/A as implemented

Milestone 1 is commit `4af6c02`. The subsequent component adds
`arm9v2_forward`, `arm9v2_rotate` and `arm9v2_execute`, with a joined
frontend/decode/RF/arithmetic-producer harness. This remains a component,
not a replacement selected by `CORE="ARM9"`.

The one common operand selector has four sources and three registered
producer records (A, M, W), each with two destination lanes. Match/age
priority drives a masked-OR data tree; it does not compute producer readiness.
Lane 1 wins a duplicate in one record, matching RF write priority. Held S
updates its snapshot through the same network, retaining a value when its
producer retires. There is no decode forwarding network or separate held
forwarding network.

D2 now distinguishes all-source pending-load locks from early-source locks.
Shifted Rm, register shift amounts, multiplier inputs, block base and SPSR
reads wait for a registered source before S. Plain ALU inputs, store data
and BX/SWP Rm may carry precomputed two-lane match tokens into A, where a
short mux selects the preceding registered result. A held A record absorbs
that value and clears its tokens. A failed younger producer preserves the
captured older fallback. The harness's locks use registered pending stage
records and private occupancy, never a condition/ALU result or cache ACK.
The eventual M/W implementation must supply registered capacity and registered
load/background return data; no three-clock load-use claim is made yet.

One five-level rotator supplies all ARM shifts, with parallel masks, sign
fill and carry. Register shifts capture Rs[7:0] for an extra S clock. Carry
preserve/RRX tokens let A use its own ordered flags without putting A flags
through S's rotator. S substitutes architectural PC/CPSR; A merges current
flags for MRS. The existing ARM9 ALU leaf performs arithmetic and NZCV in A.
Results, effective address, condition pass, branch event and feedback end in
registers. External older flush restores flags and cancels younger S/A work.

Conditional direct branches use D2's registered taken/fallthrough matches.
BX compares its registered operand/state. Redirect is a registered one-shot;
it kills younger S/A and frontend records on the next edge while retaining
its own output record and older M/W arithmetic records. Nonbranch and failed
PC-write predictions repair fallthrough. Intermediate block transfers do not
validate an architectural prediction; final load/ALU PC values wait for M/W.
Flags-only MSR is executed locally; SPSR/control MSR, CP15, exceptions and
precise retirement remain future work.

## Multiplier structural correction and measured cost

The initial S/A fit, seed 2, was **-3.904 ns at slow 100C** (-3.899 at -40C),
6,440 ALMs, 6,683 registers, four DSP blocks and two M10Ks / 15,360 bits.
All worst 30 slow-100C paths were forwarding into a DSP product register.
The worst was `issued[105]` → source match/age grant → operand select → DSP
multiply → `ll[15]`: six reported logic levels, **12.896 ns data delay**,
-0.453 ns skew. A DSP's delay is not expressed by its LUT-level count.
This placed forwarding and multiplication in the same clock.

One structural correction moves the DSP after the S/A operand registers.
The first private A clock registers four signed/unsigned half-products;
two carry-save reductions and one final sum combine them on the next clock.
Accumulation gets a separate saved-product clock. No new ordinary ALU stage
is added. There is no operand-magnitude early termination. Older M/W records
can drain while A owns its multiply slot. This is explicitly a throughput
trade, not a free retiming.

| Component measure | Before cut | After cut |
|---|---:|---:|
| DP S acceptance through registered A output | 2 clocks | 2 clocks |
| Register-shift DP, including amount capture | 3 clocks | 3 clocks |
| MUL/SMULL/UMULL component latency | 2 clocks | 3 clocks |
| MLA/SMLAL/UMLAL component latency | 3 clocks | 4 clocks |
| Independent MUL/MULL issue spacing | 1 clock | 2 clocks |
| Independent accumulate issue occupancy | 2 clocks | 3 clocks |
| Dependent unshifted ALU completion spacing | 1 clock | 1 clock |
| Trained branch arithmetic-harness record spacing | 1 clock | 1 clock |
| Joined program clocks, bus waits 0 / 3 / 9 | 263 / 401 / 677 | 270 / 401 / 677 |

The joined program completes the same 145 arithmetic harness records before
and after. At wait 0 the cut costs seven clocks (2.66%); bus stalls and queue
scheduling hide it in the other two runs. This tiny directed program is not
a compiled workload or game CPI estimate. The harness carries arithmetic
records through retained M/W producers and an RF commit edge; its complete
latency is not the final eight-stage memory/retirement schedule.

The initial fit predates additional functional checks for failed PC-write
and block-transfer predictions. Its exact execute snapshot and generated
netlist are retained and were verified byte-identical when regenerated.
A second trial with those functional fixes but the old multiplier layout
was stopped when superseded by the structural cut; it supplies no timing
measurement. Final three-seed results use the same corrected RTL/netlist.

## Remaining functional and timing risks

The memory address is registered at A output, but no D-TLB/cache request is
issued by this harness. Load formatting/late pickup, three-clock load-use,
background return arbitration, hit-under-miss retirement, store ordering and
abort base restoration are not implemented or verified in V2. Shared D-cache
behavior remains owned by the other thread. Block base/offset/address records
exist, but end-to-end LDM/STM abort and writeback behavior awaits M/W.

Control MSR, mode/SPSR changes, CP15 fences, SWI/undefined, IRQ/FIQ and precise
fault priority must be completed at the oldest architectural boundary.
ALU/load-to-PC and their return predictions are deliberately deferred rather
than treated as successful A branches. A-local flags are speculative until
retirement; M/W must restore them after older faults and mode changes.

The arithmetic harness does not validate registered cache backpressure,
cache replay or a final retirement skid. Its registered external capacity is
a contract, not permission to wire a live ACK into `i_ready` later. D2's
pending-destination masks must incorporate memory locks without introducing
readiness into the forwarding payload path. A cache output cannot become a
fourth combinational producer. The current late-pickup mux is included in
the component fit; the final M/W record placement will change routing.

The component includes neither caches/TLBs nor the merger in the fitted
netlist. Area is therefore not comparable with a complete ZAP CPU's ALMs,
and even a passing component fit does not meet the same-cache <=5% or whole
MiSTer 104 MHz gates. No whole-device build or board performance result is
claimed. Multiplier occupancy is fixed and slower after the cut; compiled
programs are needed to measure its actual contribution to CPI.
