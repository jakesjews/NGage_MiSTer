# ARM9V2 session 10 — completion and request boundaries

Work starts at `efe6811` (RTL `12bb290`), on `codex/arm9v2`. ZAP remains
the default. The two-clock late pickup, retained scalar misses, RF retiming
bound, and raw hit windows 3/4/5 are acceptance constraints, not tradeoffs in
this session. All Quartus work runs on Ubuntu, seed 2, 104 MHz, with at most
two of this session's containers and four globally. No LogicLock is used.

The Codex and Antigravity timing consults on master were read first. The
Codex reading of the actual paths is the relevant distinction: W's
`load_writer` paths reach cache metadata and collision capture **through the
late bypass and A's address adder**. They are not evidence that registering
a store enable alone removes those paths. Likewise, FCSE never changes the
cache index bits; expressing that explicitly is not itself a measured gain.

## Cut 1 — lock summaries on the update edge

The cache FSM now registers `o_lock_any <= |lock_nxt` and
`o_lock_owner <= lock_nxt[i_lock_owner_next]` beside `lock_ff <= lock_nxt`.
The registers are bounded against retiming. V2 sends the next W destination:
M's destination on RUN advance, RELOAD1 and quick reload, otherwise the
held W destination. Reset selects register zero, matching W's reset record.
A flush clears W's validity but does not change its destination independently
of that existing transfer rule. ZAP does not consume either summary.

V2 completion and its CP15 admission use these registered bits instead of
the live 64-bit reductions. Completion, retirement and reload still occur
on exactly the old edges. Normal-return readiness continues to inspect the
post-acceptance lock for its registered return tag: a miss ACK is not data.

`sim/cpu/arm9v2/lock_summary.py` extracts the actual capture expressions
from the cache FSM and proves their invariant inductively with Yosys. Its
unconstrained next bitmap covers multiple locks, simultaneous clear/install,
same-register replacement and every owner change without a single-owner
assumption. The proof and model are saved beside the fit evidence. Runtime
assertions additionally compare the summaries with the actual lock bitmap
and W one-hot owner on every edge. The full 267-run V2 source suite passes
with these assertions and every cycle/instruction pair equal to S9.

Generated-netlist acceptance: all three configurations pass 267/267 and
69/69 QEMU comparisons; all 85 windows match in both modes at all three
latencies, including raw 3/4/5. All four CPU/debug lint combinations and
`make cpu-gen-check` pass. See `arm9v2/s10-cut1-validation.json`.

Cut 1 fits at **-2.555 ns hot / -2.400 ns cold, 16,267 ALMs**. Against

## Cut 2 — compare both producer candidates before completion

D2/S and held-S matches now compare against the held `(M,W)` and advancing
`(A-or-skid,M)` pairs independently. The A-or-skid choice uses registered
memory state, not `done` or `quick_reload`. Completion selects between the
finished match bits at the existing capture edge. Writer masks still
suppress killed, condition-failed and retiring records on the same edge.

Execute does the same for held A operands. For an admitted S operand,
advance's W match reuses the existing registered S-to-M match; a source
assertion checks that reuse against the direct tag/writer calculation.
Load-pending capture uses the same parallel candidates. The existing
post-acceptance normal-return lock check and retained-operand repair stay
in place. No completion or retirement register has been inserted.

Three identical completion equations have separate `keep,maxfan=32`
roots for retirement, pipeline movement and forwarding selection. Their
equality is asserted in source simulation. The candidate comparison nodes
also carry `keep`, so the late completion mux cannot be optimized back
in front of a shared six-bit equality. Component harnesses with an already
selected producer feed the hold candidate; integrated tests exercise both
candidate sets and all reload/hold transitions.

## Cut 3 — registered translation and request descriptors

The existing M/W/skid movement is expressed once as next records and next
memory state, then captured on the same edges as before. The selected
check owner is captured alongside that movement: FCSE-adjusted aligned
address, mode, user override, format, read and write enables. FCSE is
computed when A enters M and travels with the record. The lookup's low
25 bits are explicitly independent of FCSE; that expression alone is not
credited with a timing gain.

A separate registered request predicate contains the selected W owner's
valid/memory/exception/state qualification. W's registered store bit,
byte enables and data retain their original ownership. Only registered
flush and fill-ended suppression remain at request consumption. Fault,
cacheability and hit qualification still belong to the cache; they cannot
be guessed a clock early. The short-port data path is unchanged.

The movement covers RUN advance and skid capture, held completion with
and without quick reload, RELOAD0/1, RETRY0/1, SWP's read/return/write
phases, block-base restoration and abort, and flush. Retry/fill-installation,
deferred PC/SWP return, abort restoration and flush keep their original
priority. No ACK qualifies issue or enters the forwarding comparisons.

Every-edge source assertions compare both check enables and request
presence with the old combinational schedule. Whenever either check is
active, the full address/mode/user/format tuple must agree; every active
request also compares its FCSE address. Inactive address bits are not
claimed equivalent across a CP15 PID change: both enables are zero, and
serial recovery kills old memory owners. Existing FCSE, MMU, mode,
permission and maintenance tests exercise the observable contract.

## Remaining mechanisms and the session-11 decision

The five initial families were not the complete timing limit. The new
independent endpoint reports show these remaining chains:

- **S operand selection/rotation → A right operand:** `m.load_writer`
  (`m[525]`, fanout 79) masks `ready_match`, then forwarding grant,
  operand selection, shift input and rotator enter `a.right[24]`
  (`a[144]`). **11 levels, 11.926 ns, -2.983 ns.** This is not the A late
  match or the address-to-cache comparator. Its load-owner qualifier still
  acts inside the S data selector. A future cut must keep the full producer
  match for age/pending protection while registering a separate data-ready
  grant; simply deleting the load mask would forward unavailable data.
- **Fault/permission → accepted store collision → short word:** registered
  D-TLB `o_fsr[1]` traverses `live_write`, tag-write enable, collision select
  and finished formatting into `tr_cache_words[25]`. **10 levels,
  11.816 ns, -2.852 ns.** Registering the architectural request does not
  make the cache's permission/acceptance decision early. S9's independent
  possible store word remains, but its final selection is still late.
- **Completion → queried lock owner:** cache `state_ff[6]` (CLEAN), cache
  completion, `complete_class[1]`, `done`, next-owner tag mux and 64-bit
  lock bit selection into `o_lock_owner`. **10 levels, 11.593 ns,
  -2.633 ns.** The summary is cycle-correct, but moved a selected-owner
  query onto its input. Compare held/advancing owners against next locks
  in parallel and select the finished bits, or prove a safe event-based
  owner summary; do not reintroduce an old-lock cycle.
- **Completion → architectural RF port selection:** the same cache state
  reaches `complete_class[0]~SynDup_1` (fanout 32), write-data/port selects
  and RF data muxes. **9 levels, 11.508 ns, -2.574 ns.** Fanout is bounded,
  but the selection depth remains. The RF storage retiming bound stays.
- **A bypass/adder → metadata read:** M's load-owner mask qualifies the A
  bypass, then the ALU adder, lookup selection and read-set fanout 110
  precede the valid-array selection. **9 levels, 11.343 ns, -2.418 ns.**
  This is the planned short-port cut. Short-RAM collision capture itself
  is currently -1.817 ns (8 levels, 10.779 ns).
- **D1 classification → D2 payload:** **11 levels, 11.273 ns, -2.349 ns**
  at the worse slow corner. The earlier rejected D1 experiment is not
  reinstated. Fetch's own PC recurrence is also -2.081 ns (7 levels,
  11.345 ns).

The short-RAM/metadata cut is left for S11; neither `zap_ram_simple.sv`
nor `zap_cache_tag_ram.sv` was changed in S10. Capture one lookup/write
address descriptor per cache, compare after the RAM-read edge, and bank
or partially read metadata before that edge. Valid, dirty and LRU read
captures have distinct hold/maintenance enables; preserve each ownership
and pending-write/clear priority. A single shared enable copied from the
data RAM is not sufficient. Require a cycle-exact old/new miter for byte
writes, holds, fills, HUM, cleaning, invalidation and line operations,
then the complete suites. ZAP's non-short path must remain unchanged.

I cannot credibly forecast -0.7 to 0 ns from that cache cut alone: it does
not shorten the current S→A, completion→RF, or owner-summary-input chains.
Keep the explicit post-S11 -1.5 ns decision gate. If the structural result
still misses it, make the requested `F1 F2 D1 D2 S A L M W` address-launch
stage decision (raw windows 3/5/6), rather than a seed search. That stage
addresses A→cache, **not** the presently leading S→A qualifier/rotator;
that independent cone also needs a structural cut. No extra stage or
cycle-changing fallback was implemented here.
