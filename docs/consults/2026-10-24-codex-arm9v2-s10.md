## Cut 1 — lock summaries on the update edge

The cache FSM now registers `o_lock_any <= |lock_nxt` and
`o_lock_owner <= lock_nxt[i_lock_owner_next]` beside `lock_ff <= lock_nxt`.
The registers are bounded against retiming. V2 sends the next W destination:
M's destination on RUN advance, RELOAD1 and quick reload, otherwise the
held W destination. Reset selects register zero, matching W's reset record.
A flush clears W's validity but does not change its destination independently
of that existing transfer rule. ZAP does not consume either summary.

V2 completion and its CP15 admission use these registered bits instead of
the live 64-bit reductions. Completion, retirement and reload still occur
on exactly the old edges. Normal-return readiness continues to inspect the
post-acceptance lock for its registered return tag: a miss ACK is not data.

`sim/cpu/arm9v2/lock_summary.py` extracts the actual capture expressions
from the cache FSM and proves their invariant inductively with Yosys. Its
unconstrained next bitmap covers multiple locks, simultaneous clear/install,
same-register replacement and every owner change without a single-owner
assumption. The proof and model are saved beside the fit evidence. Runtime
assertions additionally compare the summaries with the actual lock bitmap
and W one-hot owner on every edge. The full 267-run V2 source suite passes
with these assertions and every cycle/instruction pair equal to S9.

Generated-netlist acceptance: all three configurations pass 267/267 and
69/69 QEMU comparisons; all 85 windows match in both modes at all three
latencies, including raw 3/4/5. All four CPU/debug lint combinations and
`make cpu-gen-check` pass. See `arm9v2/s10-cut1-validation.json`.

## Cut 2 — compare both producer candidates before completion

D2/S and held-S matches now compare against the held `(M,W)` and advancing
`(A-or-skid,M)` pairs independently. The A-or-skid choice uses registered
memory state, not `done` or `quick_reload`. Completion selects between the
finished match bits at the existing capture edge. Writer masks still
suppress killed, condition-failed and retiring records on the same edge.

Execute does the same for held A operands. For an admitted S operand,
advance's W match reuses the existing registered S-to-M match; a source
assertion checks that reuse against the direct tag/writer calculation.
Load-pending capture uses the same parallel candidates. The existing
post-acceptance normal-return lock check and retained-operand repair stay
in place. No completion or retirement register has been inserted.

Three identical completion equations have separate `keep,maxfan=32`
roots for retirement, pipeline movement and forwarding selection. Their
equality is asserted in source simulation. The candidate comparison nodes
also carry `keep`, so the late completion mux cannot be optimized back
in front of a shared six-bit equality. Component harnesses with an already
selected producer feed the hold candidate; integrated tests exercise both
candidate sets and all reload/hold transitions.

Cut 2 verification passes: 267/267 and 69 QEMU comparisons in all three

Cut 2 fits at **-2.638 ns hot / -2.585 ns cold, 16,145 ALMs**. Global hot
slack regresses 0.083 ns; this is not a whole-core timing win. The decode
match endpoint improves by 0.220 ns, and execute's worst endpoint changes
to operand capture (`issued[106]` → `a[144]`), not the completion-selected
late-match chain. The short response now leads. RF retirement remains a
separate -2.494 ns chain; splitting next-producer matches does not remove
architectural write-port selection. Retain the verified factoring and
measure the next requested cut, rather than search seeds.
