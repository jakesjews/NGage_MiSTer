## Admission cut

The old S/A critical path decoded the pending S/A destinations into a 40-bit
mask and then indexed that mask by D2's source tags. Its result also enabled
the entire S-entry payload. The cut replaces this with four pending physical
tags and four valid bits, compared directly with the four registered D2
source tags. Only sources needed before the S/A edge participate in this
hazard, as before; plain ALU sources still use the existing late tokens.
The separate registered background-load lock bitmap is unchanged.

The S-entry payload now captures whenever that slot has capacity. The hazard
controls only its valid bit and the D2 owner's advancement, not the wide
payload enable. A valid blocked S slot still holds all its data. No instruction
can execute a speculative payload capture without its attached valid bit.
This changes clock enables, not the stage count or the instruction schedule.

D1 uses a registered rotating one-hot head. Each of its two stored instruction
slots has a local classifier; the head selects a finished class instead of
selecting the input to the classifier. Target sums, ISA classification rules,
register banking, direct-branch shortcuts and flush priority are unchanged.

## Integration issues identified before M/W

The shared cache acknowledges a background load miss on the edge that installs
its register lock. Looking at the old lock on that edge incorrectly treats
victim data as a completed load. M/W must retain the owner's metadata across
that classification boundary, register any background return before forwarding,
and arbitrate it with ordinary writes. Warm hits and non-blocking misses need
separate edge traces; a nominal stage count is not a three-clock load-use proof.

The current component harness has arithmetic-only M/W records and its own RF.
The full core must replace those with cache completion and precise retirement,
preserve the shared writeback's banked-register/exception behavior, and prevent
cache ACK/err2 from propagating combinationally through A capacity into D2.
Registered capacity requires space for the record already in flight. Fill and
retry recovery must restore held RAM lookups without touching the shared
D-cache implementation. `dhum_rtl` must pass through this full path.

## M/W integration candidate

The second milestone is **not accepted yet**. `CORE="ARM9"` selects the new
V2 integration, while ZAP remains default. All 68 architectural references
agree in both predictor modes, but `dhum_rtl` still fails and the intended
three-clock load-use schedule is not implemented. No main-core integration
or firmware boot was run. The CPU-only fits below are diagnostic evidence
for this candidate, not a release claim.

The implementation joins the existing F1/F2/D1/D2/S/A components to the
shared banked writeback and CP15. A's registered address launches the D-TLB
and cache, M supplies check/format metadata, and W owns request/retirement.
The short-port response is already registered after compare/format. A local
reservation preserves the A result accepted on the edge that discovers a
blocked request. Backend hold is then registered; recovery restores the two
held lookup records before reopening S. No cache ACK drives S admission
combinationally. Background return data/mask are already registered in the
shared cache and arbitrate through RF port C.

The implementation handles byte/halfword/sign/unaligned formatting, miss
locks, store ordering, cache/TLB replay, SWP read then permission-checked write,
load-to-PC completion, condition failure, CPSR/SPSR writes, banks, interrupts,
SWI/undefined/prefetch/data aborts, block-base restoration and CP15 fences.
The design document describes the owner and priority for each case. These
are suite-covered behaviours, not a proof for every possible bus schedule.

Integration tests exposed and fixed:

- A value hidden in the reservation while S advanced: S admission now stops
  during recovery, and the reservation participates in pending-load hazards.
- Register-shift preparation latching an old amount during that hold: it now
  waits for admission. A standalone source/generated test reproduces it.
- A condition-failed serial instruction leaving D2 fenced forever: its
  retirement now releases the fence through the normal registered redirect.
- CP15 being submitted twice across its completion handshake: submission is
  now a one-shot while the instruction record remains stable.
- A held request using the younger M load format: W owns held check/format
  metadata, including cache repair clocks.
- A request immediately after fill installation using a pre-installation
  tag result, launching a false miss over a newly dirty line: the core
  re-reads this boundary before acceptance.
- The HUM bench checking the RAM's set rather than the registered short-port
  response's set: its assertion now tracks both edges. The assertion remains
  enabled and still checks the actual returned set.

### Remaining work and stopping point

The committed admission cut is accepted. The integrated core is a measured
**experimental candidate**, not an accepted M/W milestone. The immediate
functional blocker is the short-port replacement update during HUM, in the
other engineer's protected cache files. The report and handoff retain all
failures rather than excluding them. ZAP remains the default and passes its
complete suite unchanged.

Continue in this order:

1. Resolve the cache ownership handoff and verify `dhum_rtl`, `dhold_rtl`,
   `arm9_cache_lru_rtl` and the other cache tests at all latencies and predictor
   settings, preserving the ZAP results. The proposed replacement-state cause
   has bus/source evidence but no verified cache patch yet.
2. Implement the actual three-clock S late pickup. Distinguish real destination
   writers from unused decode lanes. Qualify a registered load-return producer
   and retain/replay a dependent across a miss, abort, fill installation or
   backend hold. Simply dropping M/W from the pending list is unsafe: a miss
   ACK installs its lock on that edge, after D2 has observed the old lock.
   Keep cache ACK/readiness out of the forwarding/admission combinational path.
3. Restore W's RAS checkpoint on recovery and measure the remaining branch,
   serial/fill recovery and LDM costs in the complete core. The present
   candidate does not meet the 35% cycle target or establish game CPI.
4. Re-run the full suites, QEMU comparisons and timing windows after those
   functional/schedule changes. Then close the measured integrated paths,
   repeat seeds 2-4, and proceed to the `NGAGE_NO_DEBUG` whole-device build only
   after its CPU gate is met.

Functional risk is concentrated at the miss-classification/lock edge and
lookup recovery across fill installation, stores, aborts and background RF
arbitration. Existing references cover the implemented architectural cases;
they are not exhaustive over arbitrary interrupt/bus-error schedules. The
cacheless `ONLY_CORE` bypass and alternate endian configurations were not
validated; this candidate requires the formatted short-read cache interface.
Timing risk remains in classification, queue selection, load-hazard enables,
forwarding and RF write-through. The CPU-only fit omits whole-device routing
pressure. No firmware boot, board test, game-rate measurement, `sys/` change,
or `zap_dcache*.sv` change was made.
