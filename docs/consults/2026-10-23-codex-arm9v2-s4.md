# ARM9V2 session 4: admission boundary and M/W integration

The admission milestone from `74d046a` is complete on `codex/arm9v2`. Its
median worst-slow slack improves from **-1.729 to -0.748 ns**, with median
area falling from **6,387 to 6,094 ALMs** and no measured cycle cost. This
meets the requested approximately -1.2 ns component target. The registered
multiplier inputs are unchanged. ZAP remains default. M/W integration is next;
these component results are not a CPU/cache integration fit.

## Admission cut

The old S/A critical path decoded the pending S/A destinations into a 40-bit
mask and then indexed that mask by D2's source tags. Its result also enabled
the entire S-entry payload. The cut replaces this with four pending physical
tags and four valid bits, compared directly with the four registered D2
source tags. Only sources needed before the S/A edge participate in this
hazard, as before; plain ALU sources still use the existing late tokens.
The separate registered background-load lock bitmap is unchanged.

The S-entry payload now captures whenever that slot has capacity. The hazard
controls only its valid bit and the D2 owner's advancement, not the wide
payload enable. A valid blocked S slot still holds all its data. No instruction
can execute a speculative payload capture without its attached valid bit.
This changes clock enables, not the stage count or the instruction schedule.

D1 uses a registered rotating one-hot head. Each of its two stored instruction
slots has a local classifier; the head selects a finished class instead of
selecting the input to the classifier. Target sums, ISA classification rules,
register banking, direct-branch shortcuts and flush priority are unchanged.

## Integration issues identified before M/W

The shared cache acknowledges a background load miss on the edge that installs
its register lock. Looking at the old lock on that edge incorrectly treats
victim data as a completed load. M/W must retain the owner's metadata across
that classification boundary, register any background return before forwarding,
and arbitrate it with ordinary writes. Warm hits and non-blocking misses need
separate edge traces; a nominal stage count is not a three-clock load-use proof.

The current component harness has arithmetic-only M/W records and its own RF.
The full core must replace those with cache completion and precise retirement,
preserve the shared writeback's banked-register/exception behavior, and prevent
cache ACK/err2 from propagating combinationally through A capacity into D2.
Registered capacity requires space for the record already in flight. Fill and
retry recovery must restore held RAM lookups without touching the shared
D-cache implementation. `dhum_rtl` must pass through this full path.

## Stopping point

The admission milestone is verified and ready for its commit. The next
step is M/W, precise retirement and CORE=ARM9 integration; none is claimed
by this intermediate milestone report. The final session report will identify
the completed integration scope or its exact remaining blocker.
No changes to `sys/` or `zap_dcache*.sv`, no firmware boot, no whole-device
build and no board measurement have been made in this session.
