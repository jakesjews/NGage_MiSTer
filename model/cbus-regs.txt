# CBUS device register initial values for the reference model.
# <device> <register> <value> [ro]   # meaning, evidence (firmware RH-29 v4.60 PC)
# "ro": reads always return the value; writes are stored but do not change reads.
# Device 1 = UEMK. Register names follow TriX's DCT4 UEM model where they agree.
1 0x15 0x0008 ro   # interrupt/status read; bootstrap 0x2EE8 continues only if bit 3 (assumed: power-key power-on) or bit 4 is set; bootstrap also writes 0x200 here (0x2F54)
# Device 4: unknown chip, probably ZOCUS (guess). cbus.dll self-test 0x5037E008 requires (reg0 & 0xFF00) == 0x0400, otherwise Kern::Fault("CBus:", 25).
4 0x00 0x0400 ro   # ID/version; only the high byte is checked
